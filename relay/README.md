# Orole Jarvis relay

A stateless Cloudflare Worker (plus one Durable Object, `Hub`) that lets ElevenLabs Agents reach your
Orole daemon. The daemon opens one authenticated WebSocket to `/daemon`; the relay forwards the
custom-LLM, inbound-call and post-call requests over it. It stores nothing: no transcripts, no
numbers, no history. If the daemon is not connected, the caller hears a short goodbye.

The frame protocol lives in `internal/jarvis/relay.go`; JSON field names must match it exactly.

| Endpoint | Auth | Purpose |
| --- | --- | --- |
| `GET /daemon` (WebSocket upgrade) | `Authorization: Bearer <RELAY_TOKEN>` | The daemon's persistent connection |
| `POST /llm/chat/completions` (aliases `/llm`, `/llm/v1/chat/completions`) | header `x-orole-relay: <LLM_SECRET>` | ElevenLabs custom LLM; OpenAI-style SSE reply |
| `POST /inbound` | header `x-orole-relay: <LLM_SECRET>` | Inbound personalization webhook; returns `conversation_initiation_client_data` (with `custom_llm_extra_body.call_id`, and `lang` when the daemon sends one), 403 when the daemon refuses the caller, 503 when the daemon is offline or does not answer |
| `POST /status` | `ElevenLabs-Signature: t=<ts>,v0=<hmac_sha256(WEBHOOK_SECRET, "<ts>.<body>")>` | Post-call webhook |
| `GET /health` | none | `{ "daemon": boolean }`, no secrets |

## Turn frames (daemon -> relay)

A custom-LLM request becomes an `llm.request` frame (`id`, `callId`, `messages`); the daemon answers with frames that
carry the same `id`, and the relay streams them to ElevenLabs as OpenAI-style SSE:

| Frame | Fields | SSE |
| --- | --- | --- |
| `llm.delta` | `text` | a `delta.content` chunk |
| `llm.done` | | a `finish_reason: "stop"` chunk, `data: [DONE]`, then the stream closes |
| `llm.error` | `text` (spoken; a short default when empty) | that text, then as `llm.done` |
| `llm.tool` | `tool` (function name), `args` (a JSON object as a string, default `"{}"`) | a function call (below), then the stream closes |

`llm.tool` answers the turn with a function call instead of ending it. ElevenLabs passes the agent's system tools
(`end_call`, `skip_turn`, ...) to a custom LLM in the OpenAI `tools` parameter and runs a call that comes back in the
stream; the daemon uses `skip_turn` to keep the agent silent and waiting for the owner. The relay writes one
`chat.completion.chunk` whose `choices[0].delta.tool_calls` is
`[{"index":0,"id":"call_<random>","type":"function","function":{"name":"skip_turn","arguments":"{}"}}]`, then a chunk with an
empty delta and `finish_reason: "tool_calls"`, then `data: [DONE]`. Text deltas sent before the tool frame stay ahead of
the call. `args` that is not a JSON object is replaced by `{}`, and a frame without `tool` is ignored.

The daemon follows every `llm.tool` with an `llm.done` for the same request. The relay has already finished the stream
on the tool frame and ignores that done.

**The relay must be redeployed (`wrangler deploy`) for this to work.** An old relay ignores `llm.tool` but ends the
request at once on the `llm.done`, so the request ends empty (no text, `finish_reason: "stop"`). ElevenLabs treats an
empty answer as a failure: it retries, and after a few attempts fails the call.

Call language: the daemon puts `lang` (`"nl"` for Dutch and Auto, `"en"` for English) next to `call_id` in
`custom_llm_extra_body` (outbound calls, in the ElevenLabs outbound-call request; inbound calls, as `vars.lang` in
`inbound.answer`, which `/inbound` copies). ElevenLabs sends it back on every `/llm` request as
`elevenlabs_extra_body.lang`, and the relay speaks its own fixed lines (goodbye when the daemon is offline, "lost
connection", the default failure line) in Dutch when it is `nl`, and in English otherwise or when an older daemon sends none.

## Deploy

```
bunx wrangler@4 secret put RELAY_TOKEN      # from relay/; paste the value shown in Settings > Phone
bunx wrangler@4 secret put LLM_SECRET
bunx wrangler@4 secret put WEBHOOK_SECRET
bunx wrangler@4 deploy
```

The relay fails closed per path: a route whose own secret is unset answers 503 ("relay not configured")
(`/daemon` needs `RELAY_TOKEN`, the `/llm` paths and `/inbound` need `LLM_SECRET`, `/status` needs `WEBHOOK_SECRET`).
Set the secrets before pointing ElevenLabs or the daemon at it.

`RELAY_TOKEN` and `LLM_SECRET` are generated by the app ("Generate relay secrets") and shown once in Settings > Phone, each with
a copy button. `WEBHOOK_SECRET` is **not** generated by the app: ElevenLabs creates the post-call webhook's signing secret when
you press Connect, and the app shows it once, with a copy button. It is optional: until you set it, the relay rejects post-call
webhooks and the daemon ends calls by polling Twilio (and ElevenLabs) every 5 s. If you change the relay URL later, Connect creates a new webhook and
the app tells you the id of the old one to delete in ElevenLabs.

ElevenLabs' inbound personalization webhook and post-call webhook are settings of your whole ElevenLabs workspace; Connect sets
them for every agent in that account.

## Develop

```
bun install --cwd relay
bun run --cwd relay test
bun run --cwd relay typecheck
```

Dependencies are pinned exactly. `compatibility_date` is capped by what the pinned workerd (via
`@cloudflare/vitest-pool-workers`) supports; raise it together with the dependencies.
