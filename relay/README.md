# Orole Jarvis relay

A stateless Cloudflare Worker (plus one Durable Object, `Hub`) that lets ElevenLabs Agents reach your
Orole daemon. The daemon opens one authenticated WebSocket to `/daemon`; the relay forwards the
custom-LLM, inbound-call and post-call requests over it. It stores nothing: no transcripts, no
numbers, no history. If the daemon is not connected, the caller hears a short goodbye.

The frame protocol lives in `internal/jarvis/relay.go`; JSON field names must match it exactly.

| Endpoint | Auth | Purpose |
| --- | --- | --- |
| `GET /daemon` (WebSocket upgrade) | `Authorization: Bearer <RELAY_TOKEN>` | The daemon's persistent connection |
| `POST /llm/chat/completions` | header `x-orole-relay: <LLM_SECRET>` | ElevenLabs custom LLM; OpenAI-style SSE reply |
| `POST /inbound` | header `x-orole-relay: <LLM_SECRET>` | Inbound personalization webhook; returns `conversation_initiation_client_data` or 403 |
| `POST /status` | `ElevenLabs-Signature: t=<ts>,v0=<hmac_sha256(WEBHOOK_SECRET, "<ts>.<body>")>` | Post-call webhook |
| `GET /health` | none | `{ "daemon": boolean }`, no secrets |

## Deploy

```
bunx wrangler@4 secret put RELAY_TOKEN      # from relay/; paste the value shown in Settings > Phone
bunx wrangler@4 secret put LLM_SECRET
bunx wrangler@4 secret put WEBHOOK_SECRET
bunx wrangler@4 deploy
```

The relay fails closed: until all three secrets are set, every authenticated route answers 503
("relay not configured"). Set the secrets before pointing ElevenLabs or the daemon at it.

`RELAY_TOKEN` and `LLM_SECRET` are generated by the app ("Generate relay secrets") and shown once in Settings > Phone, each with
a copy button. `WEBHOOK_SECRET` is **not** generated by the app: ElevenLabs creates the post-call webhook's signing secret when
you press Connect, and the app shows it once, with a copy button. Until you set it, the relay rejects post-call webhooks (the
daemon still ends calls by polling ElevenLabs every 5 s). If you change the relay URL later, Connect creates a new webhook and
the app tells you the id of the old one to delete in ElevenLabs.

ElevenLabs' inbound personalization webhook and post-call webhook are settings of your whole ElevenLabs workspace; Connect sets
them for every agent in that account.

## Develop

```
bun install --cwd relay
bun run --cwd relay test
bun run --cwd relay typecheck
```

Dependencies are pinned exactly. `compatibility_date` is capped by what the pinned workerd (via
`@cloudflare/vitest-pool-workers`) supports; raise it together with the dependencies.
