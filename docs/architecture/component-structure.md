# Frontend component structure

`frontend/`: Vite, React, TypeScript strict, Tailwind v4, Zustand. The UI kit is Shipyard's coss/Base UI
components, copied (see `docs/research/upstream-attribution.md`). Look and density follow Shipyard.

```
frontend/src/
  main.tsx, App.tsx          mount, theme application, shell
  components/
    ui/                      coss/Base UI primitives (button, dialog, menu, switch, table, ...)
    shell/                   AppShell, Sidebar, SidebarProjects, StatusBar, CommandPalette, Logo
    widgets/                 Widget, WidgetGrid, registry.tsx (widget registry), builtin.tsx
    ascii/                   AsciiBackground.tsx (one canvas band per window), motion.test.ts
    tip.tsx
  features/                  one directory per view
    registry.tsx             ViewId -> lazy component; a view missing here renders NotImplemented
    home/ terminals/ projects/ worktrees/ settings/ shared/ (States.tsx: NeedsDesktop, NotConnected, NotImplemented)
  stores/                    Zustand: daemon (link + health polling), settings, ui (ViewId, focus), workspaces, projects
  lib/                       backend.ts (inDesktop), nav.ts, commands.ts (palette registry), coreCommands.tsx, utils.ts, diff.ts, projects.ts
  themes/                    builtin.ts (Orole Midnight/Obsidian/Light), custom.ts (validated custom tokens), themes.css
  mygo.ts                    GENERATED by `go tool mygo generate` from internal/app; commit it
```

## Conventions

- **One token layer**: `index.css` + `themes/themes.css`. No per-component colour constants.
- **Add a view**: create `features/<name>/`, add one line to `features/registry.tsx`. Nav ids live in `lib/nav.ts`
  and `stores/ui.ts` (`ViewId`).
- **Add a command**: `registerCommands` / `registerProvider` in `lib/commands.ts`.
- **Add a widget**: register in `components/widgets/registry.tsx`.
- **Add a setting section**: `features/settings/SettingsView.tsx` `SECTIONS` (`built: true` once rendered).
- **Backend access** goes through generated bindings (`Daemon`, `Settings`, `Workspaces`, `Terminals`, `Projects`,
  `Git`, `Worktrees`, `System`, and `events`). `lib/backend.ts` `inDesktop` is false in a plain browser; then
  the app is a **preview**: only UI preferences persist (localStorage), integrations show setup states, views that
  need the daemon show `NeedsDesktop`. No mock data in production paths.
- **ASCII art** is one canvas per window (`AsciiBand`), never per widget; motion policy is `decideMotion`
  (disabled/static/paused/reduced-motion/unfocused/low-power/intensity). See `docs/research/ascii-library.md`.
- Settings > Diagnostics also renders `features/settings/Autostart.tsx` (start-at-login switch, credential store,
  WebView2, schema version, data dir, pipe, log tail) from `System.diagnostics()`.

## First-run setup

`features/home/FirstRunGuide.tsx` presents an optional, nonmodal sequence on Home: welcome,
theme/background, live daemon status, GitHub, Mail, Drive, agents, remote machines, dashboard.
Theme and scene controls use the same settings store as Settings. Integration actions navigate
to the real setup views; they do not mark accounts connected or invent discovered capabilities.
The desktop stores the current step and dismissal under the daemon's `onboarding` setting.
Writes must succeed before leaving a step. A dismissed guide can be reopened from Home.
Browser preview progress is session-only and explicitly labelled; it never calls desktop services.
Finishing or skipping the guide is not evidence that an optional integration was configured.
Browser smoke completed all nine steps, including theme/static-background selection
and skipping every optional integration, then opened the dashboard. Installed
desktop smoke separately verified daemon-backed step/theme persistence on reload.

## Workspaces

The workspace menu opens Settings > Workspaces for real create, rename, switch,
and confirmed deletion controls. At least one workspace is retained. Desktop
mutations use the daemon's `Workspaces` service; preview mutations use localStorage.
Each workspace has its own debounce timer, and all saves/deletes are serialized
so switching cannot lose an edit or let an in-flight save recreate a deleted
workspace. Renaming clears the older pending-name snapshot before saving.
Browser smoke verified create, rename, and deletion across reloads; the rendered
management surface had zero automated axe violations. Regression tests cover
rapid switches, delayed saves, and deletion during an in-flight save.

## Sound feedback

`lib/audio.ts` owns one `@web-kits/audio` engine. `shell/AudioFeedback.tsx`
maps semantic activations to brief synthesized cues; no hover or typing sounds.
Settings > Sounds persists interface enablement and web volume. A zero volume,
unfocused/hidden window, missing user activation, or stale asynchronous activation
prevents playback. Losing focus stops voices and suspends the engine.
In-app notification cues use the source preference and only new events explicitly
marked `sound && !native`; native delivery never also plays a web notification cue.
Windows owns native-notification volume and may suppress delivery.

Browser smoke exercised real Web Audio playback, keyboard slider changes, mute,
and volume persistence after reload. The Sounds surface had zero automated axe
violations. These checks do not prove acoustic audibility or Windows toast delivery.

The installed Windows desktop's Test notification action persisted a real
`system.test` notification and reported Windows acceptance through MyGo, both with
sound enabled and disabled. The per-source silent preference survived a native
page reload. OS display and acoustic audibility remain dependent on notification
permissions, volume, and Focus Assist; API acceptance is not evidence of either.

## Home composer and monitoring

Home has New task and Running agents tabs. Launch options come from the selected
box's discovered harness capabilities and registered projects/approved directories.
Model IDs are explicit user input rather than an invented account catalog.
Harness, reasoning, project, box, and worktree choices reach daemon authorization
and actual agent launch; see `windows-terminals.md` for installed Codex evidence.

`features/system/HostActivity.tsx` uses Dither Kit area/line charts only. Host CPU
and physical memory come from daemon-owned OS sampling, separately from daemon
heap. Histories contain at most 60 real samples, with accessible history tables;
unknown intervals are not fabricated. Sampling pauses while hidden, unfocused,
or outside the viewport. Charts disable animation and bloom.

Installed-desktop smoke displayed real CPU and memory histories, disk capacity,
and host uptime; losing focus displayed the paused state. The footer uses the same
machine health source, custom box names, and coss Preview Card/Tooltip controls.
Updates appear only after MyGo confirms a newer signed release; unsigned builds
show their limitation in Settings, not a fake update action.

## Unified search

The globally mounted command palette registers commands, projects, repositories,
approved local/project files, remote files, GitHub issues/PRs, agents, terminals,
settings, Mail, and Drive. Remote files, Mail, and Drive require explicit provider
selection; All does not initiate their sensitive searches. Existing authenticated
domain APIs provide bounded results without indexing private content or forwarding
content between integrations.

Results use domain selection stores. Pending Mail-thread, Drive-file/folder and
terminal selections survive lazy view mounting. Missing terminals report an error,
not a newly created replacement shell. Provider failures remain visible alongside
successful results. Changed filters, shortened queries, and cancellation discard
stale responses. Cancellation does not undo already-issued daemon policy requests
because the existing generated bindings do not expose transport cancellation.

Browser smoke exercised the provider filters and an actual theme command; live
named-pipe smoke found Workspaces, Sounds and Plugins with exact settings-section
actions and observed no policy prompts from default search. Remote and live
Mail/Drive result navigation still requires configured external endpoints. The
desktop-required preview message names `go tool mygo dev`, not Vite-only startup.
